# 数据缺失与拆解推算参考

当直接数据缺失、口径不清或可信度不足时，使用本参考进行拆解推算。推算结果可以进入正式报告，但必须明确说明“基于哪些数据推算”。完整证据、公式、输入值、假设和置信度放入核验报告。

## 基本原则

- 先找直接披露数据；找不到或可信度不足时再拆解推算。
- 每个输入变量都要有来源、时间字段、主体、口径、单位、来源链条和可信度分数。
- 能用区间就不要输出伪精确数字。
- 把披露值、计算值、估算值、预测值和推断值分开标注。
- 不同年份、币种、地域、统计口径不一致时，不要直接计算。
- 正式报告可以呈现推算结论，但核验报告必须保留完整计算链条。

## 常用计算

```text
YoY = (本期值 - 上期值) / 上期值
CAGR = (末期值 / 初期值) ^ (1 / 年数) - 1
占比 = 部分 / 总体
均价 = 销售额 / 销量
ARPU = 收入 / 用户数
利用率 = 实际使用量 / 可用供给量
```

计算前检查：

- 输入值是否同主体。
- 输入值是否同时间范围。
- 输入值是否同地域。
- 输入值是否同单位和币种。
- 输入值是否同统计口径。
- 输入值是否一个是实际值、另一个是预测值。

## 通用拆解方法

### 量价法

```text
目标规模 = 需求量 × 平均价格
```

适用于硬件、软件授权、服务调用、消费品、设备、订单、算力、工时等。

### 用户/客户法

```text
目标规模 = 用户数或客户数 × ARPU/客单价/年均支出
```

适用于 SaaS、云服务、AI 应用、会员服务、企业软件、B2B 服务等。

### 渗透率法

```text
目标规模 = 潜在基数 × 渗透率 × 单位价值
```

适用于新兴行业、AI 渗透、自动化改造、企业采用率、智能设备等。

### 收入加总法

```text
目标规模 = 主要玩家相关收入加总 + 长尾玩家估算
```

适用于行业集中度较高、主要公司披露相关业务收入的市场。

### 自上而下法

```text
目标规模 = 上级市场规模 × 目标细分市场占比
```

适用于只有大市场规模、缺少细分市场数据的场景。

### 自下而上法

```text
目标规模 = 单个微观单元价值 × 微观单元数量
```

适用于可以从客户数、门店数、设备数、项目数、调用量、座席数、服务器数等变量加总的场景。

## 存量与供给推算

当用户要查“存量”“库存”“供给能力”“部署规模”等不易直接披露的数据时，优先寻找直接披露；没有直接披露时，可以使用代理指标：

- 历史采购量、出货量、招投标数量、交付公告。
- 财报资本开支、服务器/设备采购、供应商收入或订单。
- 产品规格、实例类型、区域可用性、上线时间。
- 价格、排队、限额、邀测、售罄、可用区数量等供给信号。
- 客户案例、合作公告、数据中心扩建、机柜数、能耗、液冷、网络配置等基础设施信号。
- 折旧、淘汰、替换周期或利用率假设。

示例逻辑：

```text
期末存量 ≈ 历史累计采购/部署量 - 淘汰量 - 转售/迁移量
可售供给 ≈ 总部署量 × 可对外销售比例 × 可用率
收入反推供给 ≈ 相关收入 / 单位价格 / 使用率
```

上述公式只能作为推算，必须标注假设和置信度。

## 核验报告中必须记录

| 字段 | 要求 |
|---|---|
| 指标 | 市场规模、存量、供给、销量、价格、用户数、ARPU、渗透率等 |
| 数值 | 原始数值，不随意改写 |
| 单位 | 金额、数量、百分比、调用量、容量等 |
| 时间 | 发布时间、事件时间、数据期间、原始来源时间、检索时间 |
| 来源 | 链接、标题、发布方 |
| 信源等级 | S/A/B/C/D |
| 可信度分数 | 0-100 |
| 数据类型 | 披露值、计算值、估算值、预测值、推断值 |
| 来源链条 | 一手、转述、引用或无法追溯 |
| 口径说明 | 地域、主体、统计范围、是否含税、是否含硬件、是否为可售供给等 |

## 正式报告中的表达

正式报告只保留读者需要的说明，例如：

```text
由于主要厂商未直接披露 GPU 存量，本文基于公开产品规格、可用区上线情况、采购/合作公告和供应链披露进行区间推算。按“历史部署信号 - 可能淘汰量”口径估算，国内主要云厂商相关 GPU 存量可能处于 X-Y 区间；完整变量、来源和假设见核验报告。
```

不要在正文中堆放完整证据表、搜索过程或长篇局限说明。
