# 报告模板

用于输出“正式报告 + 核验报告”。正式报告模板必须按用户确认的大纲调整，不要固定套用市场规模、增长、结构等章节。

## 先确认的计划模板

```markdown
# 报告大纲与核验计划

## 1. 我对需求的理解
[复述用户要解决的问题、研究对象、时间/地域范围、输出形式。]

## 2. 拟定正式报告大纲
1. [章节/段落 1]
2. [章节/段落 2]
3. [章节/段落 3]

说明：如果任务很窄，正式报告可以只是一到数段，不强制写成长报告。

## 3. 关键事实、数据与判断
| 项目 | 类型 | 为什么需要 | 可能来源 | 是否可能需要推算 |
|---|---|---|---|---|
|  | 事实/数据/判断/预测 |  |  | 是/否 |

## 4. 信源覆盖计划
| 优先级 | 信源类型 | 示例 |
|---|---|---|
| 1 | 官方/一手来源 | 官网、财报、公告、电话会、官方文档、统计机构 |
| 2 | 权威第三方 | 研报、36 氪、财新、财联社、第一财经、路透、彭博 |
| 3 | 线索来源 | 公众号、论坛、社区、转载 |

## 5. 需要确认
- [问题 1]
- [问题 2]
```

## research_report.md

正式报告要像正常咨询报告，重点是分析和结论。篇幅由任务决定，可以很短。

```markdown
# [报告标题]

[按照用户确认的大纲写作。]

[在涉及关键数据或推算时，用自然语言说明数据来源和计算逻辑。]

示例：
根据 [来源/机构/公开材料] 的数据，[主体] 在 [时间] 的 [指标] 为 [数值]。在缺少直接披露数据的情况下，本文基于 [变量 A]、[变量 B] 和 [变量 C] 进行推算，得到 [结论/区间]。完整证据、口径和计算过程见核验报告。
```
